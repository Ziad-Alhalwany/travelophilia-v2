# TP-READ-001: Security Discovery Report

## 1) Understanding of the Product Journey
**Travelophilia is an Experience + Operations System, not just a booking site.**
1. **Inspiration**: User browses Trips, Hotels, Camps, or Activities (Home/Choose Your Trip).
2. **Customization**: User requests a specific experience via "Customize Your Trip" (Day Use / Accommodation).
3. **Request**: Logic handles Egyptian vs. Non-Egyptian identity rules and submits a `TripRequest`.
4. **Operations (CRM)**: Request lands in internal CRM APIs for the team to handle (Status/Priority).
5. **Payment**: User pays via Paymob/Stripe (Integrated flow).
6. **Confirmation**: User receives confirmation/itinerary (Docs/WhatsApp).
7. **Execution**: Service delivery with follow-up (Feedback/Ambassador program).
*Key differentiate:* The system bridges the chaotic "messages/calls" world into a structured digital journey.

## 3) Observed Risks/Errors (Critical)
1. **Hardcoded Secrets**: `settings.py` contains `SECRET_KEY = 'django-insecure...'` and Database Password `"123"`. This is a critical vulnerability if pushed to prod.
2. **Debug Mode Enabled**: `DEBUG = True` is hardcoded. This leaks stack traces and environment info if active in production.
3. **Broken/Insecure Host Config**: `ALLOWED_HOSTS = []` will cause the app to fail in production, and `CORS_ALLOWED_ORIGINS` is restricted to `localhost`, blocking any real deployment or frontend integration from other domains.
4. **Duplicate Config**: `SIMPLE_JWT` settings are defined twice in `settings.py`.

## 4) 5 Actionable Suggestions
1. **Environment Variables**: Refactor `settings.py` to use `os.environ.get()` or `python-decouple` for `SECRET_KEY`, `DEBUG`, `DB_PASSWORD`, and `ALLOWED_HOSTS`.
2. **Fix CORS/CSRF**: Add trusted origins to `.env` and allow dynamic configuration for production domains.
3. **Review Auth Rate Limits**: The current throttling (30/min anon, 300/min user) might be too permissive for a public-facing API; consider tightening `anon` throttle.
4. **Sanitize `settings.py`**: Remove the duplicate `SIMPLE_JWT` block and ensure `INSTALLED_APPS` contains only necessary apps (e.g., check if `django_extensions` is needed in prod).
5. **Add Security Headers**: Ensure `SecurityMiddleware` is properly configured with HSTS, X-Content-Type-Options, etc. (currently default).
